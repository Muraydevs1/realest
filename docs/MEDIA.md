# Media & Asset Guide

How site imagery is produced, what each asset is for, and how to add media for
future Sale / Rent listings. Optimization pipeline: `scripts/optimize-media.mjs`
(sharp + ffmpeg-static, both devDependencies).

## Conventions

| Kind | Format | Size | Naming |
|---|---|---|---|
| Hero slide (full-bleed) | AVIF + WebP, 3+ widths | 640 / 960 / native (final: +1440/1920) | `hero-<slide-id>-<w>.avif` / `.webp` |
| Card cover (4:3) | WebP q≈80 | ~750–1250 w, landscape | `F<project>.webp` (front view) |
| Gallery photo | WebP q≈78 (keep JPEG if it's smaller) | native width, ≤1600 w | `<project><n>.webp` |
| Services card (3:2 slot) | WebP q≈76 | 880 w (2× the ~440px slot) | `svc-<service>.webp` |
| Video tour | H.264 MP4, CRF 26, `+faststart` | keep source resolution | `<project>vid.mp4` |
| Video poster | WebP from a representative frame | video resolution | `<project>vid-poster.webp` |
| Logo | PNG w/ alpha, tight-cropped to the art (12px safe margin) | 399×320 (display is ≤64 CSS px tall) | `logo.png` |

All images that render in fixed-aspect slots (covers, services, gallery frame)
are wrapped in aspect-ratio containers in the components, so replacing a file
never causes layout shift. Keep covers landscape ≥4:3 — portrait originals get
a dedicated landscape crop (see `Ffrafraha.webp`, cropped from `frafraha1`).

## Adding media for a future Sale / Rent listing

1. Drop the **original, full-resolution** photos/video in a folder outside
   `src/assets` (keep originals somewhere safe — the repo only holds optimized
   derivatives).
2. Produce derivatives with the same sharp/ffmpeg settings as
   `scripts/optimize-media.mjs`:
   - one landscape 4:3 cover (`F<slug>.webp`),
   - gallery WebPs at native width,
   - if there is a video: CRF-26 MP4 + a poster frame.
3. Import them in `src/assets/assets.js` and add the listing to `projectsData`
   with `category: 'sale' | 'rent'` and **verified** commercial fields only
   (the UI hides `null` fields — never guess prices/specs).
4. Site plans go in `plans[]`; only entries with `public: true` ever render.

## Hero slider

The homepage hero is a GSAP-animated carousel. **All slides are defined in one
place: `src/assets/heroSlides.js`.** The carousel (`src/components/Header.jsx`)
renders whatever that config exports — image files, labels, focal points, and
slide count are never hardcoded in JSX.

- **Asset location / naming:** `src/assets/hero-<slide-id>-<width>.{avif,webp}`
  (e.g. `hero-east-legon-640.avif`). Generated by `scripts/optimize-media.mjs`
  (see `HERO_SLIDES` there): AVIF q≈55 + WebP q≈78 at 640 / 960 / native width.
- **Recommended final sources:** landscape ≥1920×1080 (16:9 to 4:3 works;
  the frame is `object-cover`), sharp, exterior view, room for light text.
  With a ≥1920px original, generate 640 / 960 / 1440 / 1920 variants.
- **Focal points:** per-slide `focalPosition.{mobile,tablet,desktop}` maps to
  `object-position` via CSS vars (breakpoints 768 / 1024). Adjust per slide —
  don't force one universal crop.
- **Add a slide:** generate its AVIF/WebP files → add one entry (imports +
  object) in `heroSlides.js` → rebuild. Nothing else.
- **Remove / disable / reorder:** delete the entry, or set `enabled: false`
  (keeps the entry for later), or change `order`. Indicators, wrap-around,
  autoplay, and single-slide handling (controls hidden, autoplay off) adapt
  automatically; zero enabled slides logs a dev error and renders a branded
  navy fallback.
- **Replace a temporary image with a final photo:** add the new files, swap
  the six imports + srcsets in that slide's entry, flip `isTemporary` to
  false, adjust `focalPosition` if needed, rebuild, and only delete the old
  `hero-*` files after a zero-reference grep.
- **Current slides are temporary** (`isTemporary: true`): best available
  photos today are 1000–1080px wide, visibly soft on large desktops. Final
  ≥1920px company photography is still required for all three slides.
